## SEO consultant (SEO-1..10)

Read from the design doc only; did not inspect code.

- SEO-1 (§4): Exclusion rule is right (`sitemap: false`, `noindex: true`, `robots: no`, 404). Also drop redirect stubs, non-canonical pages, non-200 pages.
- SEO-2 (§4): `robots: no` is not noindex. A robots.txt Disallow stops crawling, not indexing; Google cannot see a noindex on a blocked page. Recommend `robots: no` emit `<meta name="robots" content="noindex">` and stop writing Disallow, or document `noindex: true` as the de-index key and `robots: no` as crawl-block only. Never combine Disallow with noindex. Add to §12 (changes robots.txt output).
- SEO-3 (§4): Agree `search_index: false` stays independent of the sitemap.
- SEO-4 (§4): Emit `<meta name="robots" content="noindex, follow">` for `noindex: true` and `robots: no`. Document that non-HTML files need an `X-Robots-Tag` header.
- SEO-5 (§7): Biggest risk: 404.html is only a 404 if the server sends status 404. Apache ErrorDocument, Cloudflare Pages, Netlify do; SPA-style rewrites return 200 (soft-404). Add to manual and to `audit:live`: request a random nonexistent URL and assert 404. Never redirect unknown URLs to /404.html or home.
- SEO-6 (§7): noindex on the 404 page as backup. Omit canonical on 404. Exclude from sitemap, search.json, feeds. ErrorDocument must be a local path (a full URL makes Apache 302). No meta refresh.
- SEO-7 (§3): Feeds are not an indexing problem. Exclude `feed.*` from sitemap and search.json. Do not Disallow feeds (crawlers use them for discovery). Full-text, absolutized links; item link = guid = canonical. Site/category overlap is fine; `exclude_categories` handles podcast separation.
- SEO-8 (§3.4): Autodiscovery `<link rel="alternate">` with types `application/rss+xml`, `application/atom+xml`, `application/feed+json`; distinct descriptive titles; absolute URLs; category pages advertise their own feed. staticforce and sample themes should emit by default.
- SEO-9 (sitemap lastmod): Never use build timestamp. Use frontmatter `updated`, else `date`, else source mtime. Aligns with feed `updated`. Behavior change: add to §12 if current behavior differs.
- SEO-10: Confirm robots.txt `Sitemap:` line stays absolute. Exclude 404 and noindex pages from search.json if practical.

NOTE (orchestrator, verified in src): SitemapService uses frontmatter `date`, else source mtime, else today() — it does not use a build timestamp except as a last-resort default, and it ignores an `updated` key. RobotsTxtGenerator writes a `# <datetime>` header line on every render (see documents/plan_cloudflare_pages.md §0.1).

## AEO consultant (AEO-1..10)

Read the AEO package's Feature.php (POST_RENDER 50, POST_LOOP 50).

- AEO-1 (high, §4/§7): AEO ignores sitemap exclusions. It writes a `.md` twin and calls `llmsTxtService->addPage()` for every titled page; only opt-out is `no_llms`. It never checks `noindex`, `robots: no`, `sitemap: false` or the 404. So `content/404.md` would appear in llms.txt with a `404.md` twin. Fix: shipped 404 frontmatter sets `no_llms: true`; better, the package treats `noindex`/`robots: no` as implying `no_llms`. Test that 404.md is absent from llms.txt.
- AEO-2 (high, §4): `noindex` only adds a meta tag to HTML; the `.md` twin is a separate URL with no header/meta. Either `noindex` implies `no_llms`, or `make:htaccess` adds `X-Robots-Tag: noindex` for `*.md`. `robots: no` Disallows only the HTML path, so the twin stays crawlable.
- AEO-3 (medium, §3): feeds are not in llms.txt. `feed.json` is the most AI-friendly. Recommend an `## Optional` llms.txt section linking `/feed.json` and `/feed.xml` (needs a package change or new event).

- AEO-5 (medium, §3.2/3.3): freshness signals disagree. AEO `dateModified` = source mtime; feeds use frontmatter `updated`, else `date`. mtime changes on every git checkout. One source; frontmatter `updated` first. (Package change; out of scope.)
- AEO-6 (low, §7.1): 404 is not a robots problem if the status is really 404; noindex only matters on hosts that serve 200. Sitemap/llms exclusions are the real protection.
- AEO-7 (high, §9): slug refactor changes URLs; llms.txt, twins, sitemap and feed guids all follow, but AI-cited URLs already indexed break. Keep §9 rule 4 strict. Add a check that llms.txt URLs equal sitemap URLs for the golden site.
- AEO-8 (low, §6): search index change neutral for AI crawlers. Keep `search_index: false` independent of `no_llms`; do not Disallow `search*.json`.
- AEO-9 (medium, §8): parser swap touches the `</head>` string replace the AEO package uses to inject JSON-LD. Characterization diff must assert JSON-LD blocks, `rel="llms"`, `rel="sitemap"` survive.
- AEO-10 (low): document that `feed: false`, `sitemap: false`, `no_llms` are three separate knobs; ideally one `visibility` key maps to all three.

## Security round 1 (SEC-1..12)

- SEC-1 (High, §2): router currently `return false`s to php -S; to inject it must read and echo HTML itself. Path is `getcwd() . $requestUri` with no containment. `GET /../../home/cal/.env` (curl --path-as-is) or any --allow-remote request reads outside docroot. Change: `realpath()` the target, require prefix `realpath(docroot) . '/'`, reject NUL, inject only into `.html` found that way; serve 404.html from a fixed path only.
- SEC-2 (High, §2): router written to `sys_get_temp_dir()/staticforge-devserver-router-<pid>.php` via `file_put_contents` (follows symlinks, predictable name, executable PHP) — another local user can pre-create/swap it. New `.version` file same problem. Change: `mkdir(0700)` private dir with random name (`bin2hex(random_bytes(8))`), router + version file inside, write via temp+rename, remove dir on cleanup.
- SEC-3 (Medium, §2): launch server via `proc_open` argv array with explicit `$env` (for `PHP_CLI_SERVER_WORKERS`) instead of `popen` shell string. Reload endpoint GET-only/read-only, no CORS, `Cache-Control: no-store`; state that no HTTP request can trigger a build. Watcher must not follow symlinks.
- SEC-4 (Medium, §3): build Atom with XMLWriter/DOM, never string concat or CDATA (`]]>` breaks out); strip XML-1.0-invalid control chars; JSON Feed via `json_encode(..., JSON_THROW_ON_ERROR)`.
- SEC-5 (Medium, §3): site feed would publish pages the author hid. `noindex`, `robots: no`, `sitemap: false`, draft, 404 must also exclude a page from site feeds by default; test it.
- SEC-6 (High, §5): prune/rollback act on remote data although §11 says IDs never derive from remote data. Accept only entries matching a strict build-ID regex (e.g. `^\d{8}T\d{6}-[a-f0-9]{8}$`); validate `readlink(current)` against `releases/<valid-id>`; never prune current or anything newer; prune needs recursive delete, contradicting "non-recursive deletes retained" — implement recursion with `lstat`, delete symlinks as links, never descend into them, don't use phpseclib recursive delete; apply the delete guard to prune too.
- SEC-7 (High, §5): `SiteUploader.php:152` runs `processManifestCleanup` even when `errorCount > 0`; only the manifest write is gated. Partial network failure can mass-delete. Invariant becomes: files → deletes only if errorCount == 0 → manifest. Treat `--no-interaction` and non-TTY as non-interactive for the guard.
- SEC-8 (Medium, §5): if docroot is `<remote>` not `<remote>/current`, every retained release is web-reachable (incl. deliberately removed content); manifest readable on nginx/Cloudflare which ignore .htaccess. Store manifests under `<remote>/manifests/` outside the served tree; `audit:config` fetches a canary to confirm only `current` is served; document that rollback republishes removed content.
- SEC-9 (Medium, §5): remove-then-create fallback can leave the site down. Without `posix-rename`, abort unless `--allow-nonatomic`. Always `readlink` after swap to verify. Test phpseclib `symlink()` argument order.
- SEC-10 (High, §9): `CategoriesService::sanitizeCategoryName` (CategoriesService.php:164) returns `''` for all-symbol input; used as a path, the category index lands at `public/index.html`, overwriting the home page. Robots falls back to the unsanitized input if preg_replace returns null. "Preserve behavior" must not preserve these. `Slugger` asserts postcondition (`^[a-z0-9]+(-[a-z0-9]+)*$` for `category()`) and throws on violation/preg failure; callers treat a throw as a build error for that page. Treat as a security fix, not needing owner sign-off under rule 4.
- SEC-11 (Low, §8): `Dom\HTMLDocument` is HTML5, no DTD/entity processing, XXE n/a. Never use `Dom\XMLDocument`/`loadXML` with NOENT/DTDLOAD for content; serialize with `saveHtml`. Search extraction may change (`<template>`/`<noscript>`). Confirm search JS uses `textContent` not `innerHTML`.
- SEC-12 (Low, §7): 404 search box/scripts must not write `location.pathname`/`location.search` into the DOM as HTML.

## Devil's advocate (DA-1..11) — verified against src/

Verdict: don't proceed as drafted.

- DA-1 (blocker, §5.2): design claims upload order "files -> (no delete) -> manifest last. Already true". Actual: upload, then delete, then manifest. A failed upload is left out of `newManifest` (SiteUploader.php:133-140) and `processManifestCleanup` still runs regardless of `errorCount` (:152), so the live copy of a CHANGED file whose re-upload failed gets deleted. One transient SFTP error on an episode page removes it from the server. Fix: skip cleanup when `errorCount > 0` and treat failed uploads as "keep" in the diff. Ship this before the delete guard. (Same bug as SEC-7. This is a bug in shipped 3.3.6 code.)
- DA-2 (blocker, §2.2): watch mode can't work in the existing loop. The "100 ms tick" is `fgets($process)` on a blocking `popen` stream (DevServerCommand.php:121-142); with no requests nothing prints and the watcher never runs. Switch to `proc_open` with non-blocking pipes + `stream_select`; say so in the design.
- DA-3 (major, §2.2): injection won't reach real pages: the router returns `false` for existing files/directory indexes (DevServerCommand.php:215-224) so PHP serves them and output buffering never sees them. Under `--watch` the router must `readfile` HTML itself incl. directory-index resolution.
- DA-4 (major): the podcast guarantee is broken by G, not B. Category feed `content` is rendered HTML (RssFeedService.php:54-55, 208) that passes through the DOM heading-id fix (MarkdownRendererService.php:160). A parser swap changes serialization, so every episode's `content:encoded` changes and breaks §3.5's own byte-for-byte test; it also changes every HTML page's hash so the next `site:upload` re-uploads the whole site. Defer G (see 13.5) or record that category-feed bytes change.
- DA-5 (major): "untouched" contradicts extracting `FeedItemCollector` from `collectCategoryFiles` (the podcast path). The Podcast feature is not in this repo; nothing under src/ or Features/ listens to `RSS_*`, so a "podcast-style fixture" can't prove compatibility. ## Developer feasibility (DEV-1..11) — read code + vendor source; nothing run against a real server

- DEV-1 (A): `startServer()` (DevServerCommand.php:106-148) uses `popen` + blocking `fgets()`; when idle it blocks so the poll never runs. - DEV-2 (A): router returns `false` for existing files/dir-index so the built-in server serves natively and `ob_start` can't inject.
