# StaticForge v3

**Status:** Approved. Application code has not been changed.

**Sources:** Interview constraints; specialist audits ([security](5456dc54-27de-4b2d-bf43-324d503f3071), [backend](370cc044-fb97-45f8-af14-7655ce88a442), [phpstan](43040be6-8fcf-41f5-bccd-b2687a86ca9b), [unit-test-writer](5dcf8741-f613-4b6b-b419-9e3e568444d4), [feature-researcher](515fb7a6-c176-4eb4-9b85-37634956ad40), [dba](3551a0e3-67f3-4610-8605-c8ece127dfc1), [frontend](69b3c6f7-c65a-4457-8a80-7af8e7c51681)); [architect](8c8f1b31-5660-46c9-85c7-b95098c0e511) synthesis; [devils-advocate](e2e9101b-36d7-4fd5-8760-3578aad46e97) pressure test.

---

## 1. Overview

StaticForge v2 is a working event-driven PHP SSG. The nine-step pipeline, Feature plugin model, incremental `FileProcessor` writes, and Twig autoescape are worth keeping.

It is **not** demonstration-quality PHP in 2026. The v2 DI guide was never rolled out: Features still `new` services in `register()`, listeners take `Container` plus `array<string, mixed>`, agent docs describe a database that does not exist, and several security holes are real (entire `.env` in Twig, search `innerHTML`, SFTP without host-key checks).

**v3 is** an in-place, tests-first modernization to PHP 8.5: finish DI, typed events with the **same event names**, PathGuard, template-context allowlist, delete dead code and documentation lies, fix listed bugs, replace obscure code. Feature PHP may break. A **runnable** migrator must bring an existing Feature directory into the v3 contract (a markdown guide alone is not enough). Content, frontmatter, `siteconfig.yaml` keys, and command names stay. New YAML keys only as aliases.

**v3 is not** a greenfield rewrite, a Feature-extraction project, a product cut, an npm/SPA pipeline, a Calendar feature, or a PHPStan level-9 bump in place of real types.

**Verdict today:** No. Competent production PHP 8.4 with aspirational docs, not PADI demonstration quality.

## 2. Constraints

- Content, frontmatter, and `siteconfig.yaml` keep working. Aliases allowed; silent renames are not.
- Command names stay (`site:render`, `site:upload`, `site:init`, `site:devserver`, `audit:*`, `make:*`, `feature:*`).
- Feature PHP internals may break. Ship `documents/v3_feature_migration_guide.md` **and** a CLI migrator that can be run against a Feature directory (`src/Features/{Name}`, `Features/{Name}`, or a Composer package checkout) and rewrite it into spec. If a kernel change would leave existing Features unloadable, the migrator ships in the same workstream — not as a follow-up. Dry-run is the default; write mode is explicit.
- Delete dead code. Replace obscure code. **Do not delete functionality.** Features stay in this tree.
- Characterization of **user-visible** behavior first. Those tests are not edited during a refactor.
- Tests may change for listed bugs/security **and** for the v3 Feature API migration (see §7).
- PHP `^8.5`. Use 8.5 syntax when it makes the lesson clearer, not as trophies.
- Docs lockstep: PHPDoc, architecture guide, HTML docs in `content/` (https://calevans.com/staticforge), **and** `CLAUDE.md` / `.github/instructions` so agents stop generating a phantom DB.
- PADI bar: a PHP developer reading a file should think “that’s how it’s done.”

## 3. Devil’s-advocate resolutions (load-bearing)

The architect plan was attacked. These four points would have made the plan invalid if left fuzzy. They are now decisions, not open questions. Override them explicitly if you disagree.

### 3.1 Characterization grain

**Freeze:** `site:render` artifacts (`public/` HTML, sitemap, RSS, `search.json`, copied assets), CLI command list/help, and “this frontmatter/siteconfig still builds.”

**Do not freeze:** `EventManager::fire(Container, array)` shapes, Feature handler signatures, or `EventManager::list()`. Those tests **must** change in the typed-event workstream. That is the v3 Feature API break, listed here so it is not a silent test rewrite.

The migrator (`feature:migrate`) is how in-tree Features, `Features/`, and Composer checkouts get the new signatures. The unit-test updates are the lock that the new signatures are real; the migrator is how a Feature that is not this repo’s Core still compiles.

### 3.2 Require-dev Composer Features

This repo’s docs site loads `calevans/staticforge-chapternav`, `staticforge-google-analytics`, `staticforge-social-metadata`, and `answer-engine-optimization` via `extra.staticforge.feature`. A listener-signature change without matching package releases **breaks this site**.

**Rule:** Do not tag `eicc/staticforge` 3.0.0 until those four packages have been run through `feature:migrate` (or an equivalent manual rewrite) and released. No long-lived dual-signature adapter — that would become two APIs. Same-day release train. The migrator is the mechanism; package releases are the proof.

### 3.3 SFTP host-key checking (TOFU)

Today `SftpClient::connect()` does `new SFTP($host, $port)` then `login()`. phpseclib does **not** check the server’s host key unless you pin it. Anyone who can sit on the network between you and `washington` can present a fake SSH server, catch `SFTP_PASSWORD` / the private key, and serve or steal a tree. TLS-style “we used SSH” is not host authentication.

**Trust on first use** means: the first time `site:upload` talks to `SFTP_HOST`, it accepts the presented server key, writes it to `known_hosts` (next to the identity key, or `~/.ssh/known_hosts`), and continues. The operator does not set a pin and does not run `ssh` first. They must still get **`SFTP_HOST` right** — a first-connect MITM is accepted by design, same as OpenSSH with `StrictHostKeyChecking=accept-new`.

Later connects: pin against the stored key. **Mismatch refuses** (fail closed on change, not on first sight). Optional `SFTP_HOST_KEY` still overrides when set.

**Fail open** (warn and continue forever) is not a fix. Operators will ignore the warning; MITM still works after the first connect.

Not a siteconfig/content break. Document in `.env.example` and `content/`. Tests updated as a listed security fix.

### 3.4 HTML deltas vs “pure security”

| Item | v3 treatment |
|---|---|
| Twig context allowlist | **Do it.** Stopping `.env` in templates is a security fix. List any template variable that disappears. |
| Search `innerHTML` → DOM APIs | **Do it.** Listed HTML/JS delta. |
| Cache-bust all local assets | **Do it.** Query strings change; listed. |
| CommonMark `DisallowedRawHtml` | **Do not enable by default.** Add an explicit trust-mode config (alias); default remains today’s “raw HTML allowed.” Flip only after a `content/` corpus diff and owner OK. |
| Wire more Features through `AssetManager` | **Do not** in the security pass. AssetManager is already in the container. `staticforce/base.html.twig` hardcodes `main.js` / `search.js`. Extra `addScript` would duplicate tags. Wiring is a later listed HTML delta with a page diff. |

- File-based runtime. No database in Composer or `src/`. Real stores: `content/`, `siteconfig.yaml` / `siteconfig.d/`, `.env`, Twig, `public/`, `search.json`, SFTP manifest, mtime cache.
- Twig autoescape `html`. Vanilla CSS/JS. No product npm.
- PHPStan level 8 + bleedingEdge + ShipMonk. No baseline. Stay at 8 until events/DTOs exist; do not jump to 9 on `mixed`.
- Existing YAML keys, including unused `calendars:` (harmless no-op; do **not** invent a Calendar Feature).
- Tags, Categories, CategoryIndex (dedupe Pagination **code**, keep all three Features).
- Category-gated RSS (current product, not a bug).
- `site:upload` (harden, do not delete). Agent “Git-only” means do not SSH-patch the generator on `jeevs`. Upload of static `public/` to `washington` stays.
- `{{ form() }}` token (not ShortcodeManager). Document it correctly; do not force it into `[form]`.
- INI-in-HTML-comment stripper until those **tests** are migrated (production homepage is YAML-in-HTML-comment; several tests still author INI).
- `FeedExtensionInterface` / `RssBuilder::addExtension` as a published hook (`RSS_BUILDER_INIT`, podcast docs). Untested here ≠ unused as API. Keep; add a characterization test if missing.
- `AssetManager` class. Do not delete. Do not newly wire Features until §3.4.

Kernel vs optional is **clarity only** (`disabled_features`). Kernel to build a site: `SiteBuilder`, `MarkdownRenderer`, `HtmlRenderer`, `ShortcodeProcessor`, `TemplateAssets`, `MenuBuilder`, `CacheBuster`. Everything else is disable-able. CLI Features (`Deployment`, `DevServer`, `FeatureTools`) stay in-tree.

## 6. Target architecture

### 6.1 Language and packaging

- `composer.json`: `"php": "^8.5"`, `"version": "3.0.0"`. Lando is already `php:8.5`.
- Commit `composer.lock`. Stop gitignoring it. Generate the lock **on 8.5** after the constraint bump so it is not an 8.4-unreadable 8.5 lock sitting on a `^8.4` constraint.
- Set PHPStan `phpVersion: 8.5.0` (or equivalent) so 8.5 syntax is actually checked.
- `declare(strict_types=1)` on every PHP file, including Feature entry points that lack it today.
- Constructor promotion, `readonly` DTOs, `private(set)` where it clarifies. Enums for closed internal sets — **not** as the public event-name contract (strings stay for Composer Features and docs).
- Align Symfony component majors (console/yaml vs http-client/dom-crawler) to one line.
- Adding **pcov** to `.lando.yml` requires a human `lando rebuild` (agents must not rebuild). Same change set: phpunit coverage reporter. Until then the 80% rule cannot be measured.

### 6.2 Data structures

| Type | Role |
|---|---|
| `Frontmatter` | Parsed YAML. Known fields + `extra`. Reserved keys (`content`, `app_root`, `OUTPUT_DIR`, credential-shaped names) cannot be overwritten by YAML. |
| `DiscoveredFile` | `path`, `url`, `Frontmatter`. Replaces untyped `discovered_files[]` rows. |
| `Event` | `string $name` matching today’s names. |
| `RenderEvent` | File, frontmatter, contents, `outputPath`, skip/cache flags. |
| `ConsoleInitEvent` | Symfony Console `Application`. |
| `UploadCheckFileEvent` | Today’s `UPLOAD_CHECK_FILE` keys as properties. |
| `SiteConfig` | Readonly view of merged `siteconfig.yaml` — inject this, not the whole Container, into Features that need config. |
| Template context | Explicit allowlist (site identity, menus, page fields, `content`, `cache_buster`, `site_base_url`, public form fields). Never `getAllVariables()`. |

`EICC\Utils\Container` stays. Do not vendor-patch it. Pipeline stops being `array<string, mixed>`.

### 6.3 Class structure

```
src/Core/
  Application.php          # names unchanged; no duplicate writer
  EventManager.php         # Event objects; drop unused registerEvent
  FeatureManager.php       # factory; no new $className(); no require_once Feature.php
  FeatureFactory.php       # NEW — reflection + Container::get
  PathGuard.php            # NEW
  OutputWriter.php         # NEW — absolute paths under OUTPUT_DIR; rewrites allowed
  AssetManager.php         # KEEP; do not newly wire until listed HTML delta
  Dto/Frontmatter.php
  Dto/DiscoveredFile.php
  Events/Event.php
  Events/RenderEvent.php
  ...
src/Services/
  TemplateContextFactory.php
  PaginationService.php    # shared
  Upload/SftpClient.php    # host-key pin
src/Features/*/Feature.php # constructor DI, strict_types, typed listeners
```

`src/Core` changes are in scope: the kernel **is** the DI/event/path story. Do not grow a god-`Application`.

### 6.4 DI (finish v2 for real)

Public Feature contract stays `register(EventManager $eventManager): void` — binding only.

- Constructor-inject logger and services. No `new Service` in `register()`.
- `FeatureManager`: no `new $className()` fallback. Missing dep = load failure (log + skip).
- Drop `setContainer()` as the injection story.
- Bootstrap registers EventManager, FeatureManager, FileDiscovery, FileProcessor, OutputWriter, PathGuard, TemplateRenderer, TemplateContextFactory, AssetManager, MarkdownProcessor, ContentExtractor, per-Feature services.
- In-tree gold standard is constructor-injected Feature + readonly config DTO. ResponsiveImages is the closest today and is **not** finished (still `new`s in `register()`).

### 6.5 Event pipeline hooks

Keep **names**. Internals become objects. Docs describe objects; the broadcast schedule does not change.

`EventManager::fire(string $name, Event $event): Event`. Listeners: `handleRender(RenderEvent $event): void` — mutate the event; **do not** take Container as argument 1.

This is a hard break for Composer Features. See §3.2.

### 6.6 PathGuard and OutputWriter

- `PathGuard::resolveInside(string $path, string $root): string` — realpath, trailing separator, reject `..`. One policy for stream wrappers (tests), not copied `vfs://` `if`s in Features.
- `OutputWriter::write(string $absolutePath, string $contents): void` — must stay under `OUTPUT_DIR`. **Accept absolute paths** (Sitemap/RSS/Search already join `$outputDir . '/sitemap.xml'`). **Allow rewrite** of an existing file (TemplateAssets CSS bundling rewrites `public/assets/css/main.css`). Atomic temp + rename where FileProcessor already does that.
- One write path for **generated site files**: FileProcessor + POST_LOOP artifacts. `Application::renderSingleFile` delegates to FileProcessor; delete `Application::writeOutputFile`.
- Not everything is OutputWriter: `InitCommand` / `ContentCreatorCommand` / `FeatureCreateCommand` write source via PathGuard vs `SOURCE_DIR` / `src/Features`. Weather TTL cache and DevServer router live **outside** `OUTPUT_DIR` (router must not be `public/.ht.route.php`).

PathGuard as a Core helper can exist before Feature DI. Landing it **does** edit Feature services (the `strpos` checks). That is expected: Features get touched in the security slice and again in the DI slice. Do not pretend otherwise.

### 6.7 Feature API migrator (hard requirement)

A markdown guide is not a migration. If a kernel change would make existing Features fail to load, v3 ships a command that rewrites a Feature directory into spec:

```text
lando php bin/staticforge.php feature:migrate path/to/FeatureDir [--write]
```

Default is dry-run (print the diff). `--write` applies it. Target may be `src/Features/{Name}`, project `Features/{Name}`, or a Composer package checkout that contains `Feature.php`.

**It must transform, at minimum:**

- `register(EventManager $eventManager, Container $container)` → `register(EventManager $eventManager)` (today’s `feature:create` scaffold still emits the v1 two-arg form).
- `new FooService(...)` inside `register()` → constructor property + leave a TODO where the service must be registered in the container.
- `handleX(Container $container, array $parameters): array` → `handleX(RenderEvent|Event $event): void` with property moves (`$parameters['rendered_content']` → `$event->renderedContent`, etc.).
- Add `declare(strict_types=1);` if missing.

**It must not:** invent business logic, silently drop event names, or rewrite tests (those follow §7). If a transform is ambiguous, it fails that file with a diagnostic instead of guessing.

`feature:create` is updated to emit **already-migrated** code so new Features never need the migrator. In-tree Features and the four require-dev packages are proof: run the migrator on them in workstream 8, then release. `documents/v3_feature_migration_guide.md` documents the command; it does not replace it.

## 7. Testing strategy

1. Before changing a class for **behavior-preserving** cleanup, a passing test of **user-visible** behavior must exist (render output, CLI, public files).
2. During that refactor, do not edit those tests.
3. **Allowed test changes:**
   - Every item in §8 (bugs/security).
   - EventManager / Feature handler unit tests in the typed-event workstream (§3.1).
   - New tests that lock new security behavior (allowlist, host-key, PathGuard).
   - `InitCommandTest` cwd leak.
4. **Do not fold** duplicate `*FeatureTest.php` vs `Features/{Name}/FeatureTest.php` during a Feature rewrite. Optional hygiene pass after DI, owner-approved.
5. Do not leave mock-theater `EventManagerTest` listeners as the teaching example after workstream 8. Demonstration quality applies to tests too.
6. Coverage: pcov + phpunit coverage config, then ≥80% on **changed** Feature/Core paths. Unenforceable until Lando has a coverage driver.
7. Write characterization for `src/Features/Search/Feature.php` before rewriting it (services are tested; the Feature is not).
8. Stay on PHPUnit 10.x unless 8.5 forces a bump.
9. Verify gate: `lando phpunit` and `lando php bin/staticforge.php site:render`.

## 10. Workstreams (sequence)

No big-bang. Each slice: tests that match §7 → change → phpstan → `lando phpunit` + `site:render` → docs.

1. **Truth pass** — Phantom DB, in-tree S3 env/example/comments, version strings, `UPLOAD_CHECK_FILE` name, calendar demo honesty, Forms token docs. Delete `.bak`, Jest `package.json`, unused fixtures. Search template `init()` vs `search.engine`.
2. **Test infrastructure** — Owner adds pcov (rebuild). Coverage config. Search `Feature.php` characterization. InitCommandTest cwd (#23).
3. **Security A (build output)** — PathGuard + OutputWriter + template allowlist + reserved frontmatter + CSS import jail. CommonMark **config hook only**, default unchanged (#1–2, #5, #8–9, #10 as config).
4. **Security B (clients)** — Search XSS/labels, SFTP host-key, DevServer router, audit SSRF, weather encoding, forms `https:` (#3–4, #6–7, #11–13).
5. **Lockfile + PHP 8.5** — Constraint, phpstan `phpVersion`, commit lockfile, Symfony align (#14, #26).
6. **Reachable CLI** — Register `audit:content`; fix `render:site` help (#16, #21).
7. **DI completion** — FeatureFactory, bootstrap map, Features one-by-one. Frozen **artifact** tests. Do not fold duplicate unit files.
8. **Typed events + migrator** — `RenderEvent` / DTOs; `feature:migrate` (dry-run then `--write`); run it on in-tree Features and the four require-dev package checkouts; **update EventManager/Feature unit tests**; `#[EventListener]`; drop Container-as-arg-1. `feature:create` scaffold last (#24) so it emits v3 code. **Do not tag 3.0.0 until migrated packages are released.**
9. **Obscure-code replacement** — Shared Pagination; FileProcessor-only page writer; production vfs `if`s removed; theme bugs (#18–20, #25). AssetManager wiring only with an accepted HTML diff.
10. **v3 migration guide** — Documents `feature:migrate`. Does not replace it. Fix the v2 guide’s fake `listen()` API while we are there.

## 13. Validity

This plan is valid if those constraints and §3 resolutions hold: in-place cleanup, event **names** stable, content/siteconfig/commands stable, Features in-tree, upload hardened not deleted, Calendar not invented, artifact-level characterization, listed HTML/security deltas, a runnable `feature:migrate` for any Feature-API break, Composer Features migrated and released with 3.0.0.

It becomes invalid if v3 extracts Features out of the tree, deletes upload/taxonomy/RSS, silently renames YAML or commands, adds npm as a product pipeline, freezes EventManager array tests and still claims typed events, tags 3.0.0 with broken chapternav/GA/social/AEO, ships a Feature-API break with only a markdown guide, or enables a Markdown HTML denylist without a corpus diff and an explicit config default.

**Can we remove code and still make everything work?** Yes: dead files, unused Jest tooling, documentation lies, duplicate Pagination *implementations*, unused `registerEvent` API. No: Features, `site:upload`, taxonomy, RSS, published extension hooks.

**Is the code reference-level PHP today?** No. PHPStan 8 is disciplined; the language floor is 8.4/8.5 while the idiom is 8.0-era classes and a mixed-bag pipeline. v3 is the demonstration-quality pass, not a rewrite of the product.
